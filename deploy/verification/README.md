# Disposable Monitoring Verification Lab

This directory contains a local-only Prometheus, Alertmanager, synthetic metric
source, and test receiver. It is a verification fixture, not a production
monitoring deployment and does not require credentials or external paging.

## Prerequisites

- Docker Engine with Compose v2
- Free local ports `8090` and `9090`

Start the healthy path manually:

```bash
cd deploy/verification
OPSBENCH_SIGNAL_MODE=healthy docker compose up -d
curl http://127.0.0.1:8090/health
curl http://127.0.0.1:9090/-/ready
curl http://127.0.0.1:8090/events
```

Run the bounded smoke test instead. It starts an isolated Compose project,
waits for readiness, verifies the receiver accepts the alert generated by
Prometheus and Alertmanager, and removes the project in a cleanup trap:

```bash
scripts/verification_lab_smoke.sh
```

The smoke test also supports deterministic local failure fixtures:

```bash
scripts/verification_lab_smoke.sh missing_collection
scripts/verification_lab_smoke.sh invalid_notification
```

`missing_collection` serves a zero signal and must not produce a receiver event.
`invalid_notification` sends a deliberately malformed payload directly to the
receiver and expects HTTP 422. Neither mode sends external notifications.

The receiver stores only bounded synthetic JSON events in the Compose volume.
The lab does not yet claim full Gate B coverage: routing mismatch, corrected
reruns, timeout evidence, and sanitized report export remain follow-up work.

Runtime status: Compose configuration, YAML, Python, and shell validation are
covered by repository tests. The healthy-path Docker smoke test must still be
run on a host with a working Docker daemon before this lab is counted as an
end-to-end verification result.
